## 方案一：用小型纯函数串起更新、规划与报告

### 搭建顺序

1. 先保留通用 `updateById`，再由 `completeTask` 传入任务专属更新回调。
2. 用独立函数完成筛选和排序，避免排序直接改变调用者数组。
3. 最后遍历更新后的任务构建状态计数与总时长报告。

### 类型与数据流

`original` → 不可变更新 → `updated` → 筛选/排序与统计 → 两类结果。

### 关键自检点

- 只有命中任务及其所在引用路径需要新对象，未命中项可以复用。
- `sort` 会原地修改数组，调用前必须确认操作的是新数组。
