## 标准结构

先把“会员、金额边界、没有优惠券”组合成一个有业务含义的布尔变量，再进入一条互斥的 `if / else if / else` 链。分支顺序就是业务优先级：一旦前面的条件成立，后面不再执行。

## 条件追踪

针对每个分支分别写下：输入条件、比较结果、是否进入、进入后修改哪个变量。尤其测试恰好位于边界的订单，以及多个规则同时看似满足的订单。

## 自检

- 组合条件同时使用 `&&` 与 `!`。
- 高优先级规则先判断。
- 互斥规则不是多个独立 `if`。
- 应付金额在优惠确定后，使用两个变量重新计算。
