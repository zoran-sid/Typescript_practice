## 方案一：按调用者需要分别保留四种关系

### 搭建顺序

1. 先声明渠道与地址位置固定的 `DeliveryPair`，不要放宽成普通字符串数组。
2. 让 `invoke` 用同一个参数元组连接原函数和转发实参，并原样交回返回值。
3. 为单地址与地址数组分别写公开重载，在联合实现中收窄；最后用 `.call` 提供账单上下文。

### 类型与数据流

渠道元组 → 描述；函数与参数元组 → 金额；单个/批量地址 → 对应结果；调用上下文 → 通知前缀。

### 关键自检点

- 重载解决的是“输入形状决定返回形状”，不要拿一个宽泛联合让调用者重新判断。
- `this` 不属于 `Args`；`invoke` 也不应退化成 `unknown[]` 参数配 `unknown` 返回值。
