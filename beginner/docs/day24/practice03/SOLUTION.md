## 方案一：筛出可信订单后再进行金额计算

### 搭建顺序

1. 声明订单最小模型，并保留 `isRecord`、`isOrder` 的守卫结构。
2. 确认顶层确实为数组，再逐项过滤出通过守卫的订单。
3. 最后在已收窄的订单数组上统计金额并格式化输出。

### 类型与数据流

订单 JSON → `unknown` → 数组检查 → 单项守卫 → `Order[]` → 金额汇总。

### 关键自检点

- 数量与单价都要验证类型及题目要求的范围。
- 无效订单不能以默认零值混入统计。
