## 方案一：通过接口组合审计依赖

### 搭建顺序

1. 先声明最小 `AuditSink`，再让内存实现自己管理记录数组。
2. `PaymentService` 只依赖接口；在 `pay` 中先验证输入，再计算、记录、返回。
3. 依次运行成功扣款和失败扣款，比较失败前后的审计数量。

### 类型与数据流

输入 → 校验 → 计算 → `AuditSink.record` → 返回；非法输入 → 抛错且跳过记录。

### 关键自检点

- 审计数组留在 `MemoryAuditSink` 内部，只通过 `count`、`last()` 观察。
- 记录动作必须在所有校验之后；否则失败请求也会留下像成功一样的审计。
