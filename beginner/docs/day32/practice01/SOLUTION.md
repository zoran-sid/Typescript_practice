## 方案一：装饰器保留签名，Mixin 扩展实例，组合注入行为

### 搭建顺序

1. 先保留标准方法装饰器的 `This`、参数元组和返回类型骨架。
2. 包装函数转发原 `this` 与全部参数；类装饰器只读取上下文信息。
3. Mixin 返回交叉类型，消息服务只依赖 Formatter 接口并由构造器接收实现。

### 类型与数据流

原方法 → 装饰器包装 → 同签名方法；实例 → Mixin → 扩展实例；Formatter → Service。

### 关键自检点

- 装饰器不要改变原方法同步/异步性质或丢失 `this`。
- Mixin 新能力不应抹掉原实例能力，服务不应在内部写死具体格式器。
