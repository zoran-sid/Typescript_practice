# Day 25 参考思路

## 练习 01：只替换命中项

`map` 总会建立新数组。条件表达式让命中项使用 `{ ...task, status: "done" }` 建立新对象，未命中项直接返回 `task`。所以旧数组不变，且无需复制没有变化的对象。

## 练习 02：保护排序前的数据

`filter` 本身返回新数组，因此可以继续对筛选结果调用会原地修改的 `sort`。若没有先 `filter`，应写 `[...tasks].sort(...)` 或使用新运行时提供的 `toSorted`。

## 练习 03：完整状态表

先创建 `{ todo: 0, doing: 0, done: 0 }`。`Record<Status, number>` 会在漏键或拼错键时提醒你。循环中用 `counts[task.status] += 1`，同时累加分钟数。

## 练习 04：泛型表达关系

约束 `T extends { readonly id: string }` 说明任何传入项至少有字符串 id。回调接收并返回同一个 `T`，所以 `Note[]` 进去仍得到 `Note[]`；它也可以复用于其他带 id 的实体。

## 间隔复习

- 展开语法是浅复制，不是运行时冻结。
- `readonly` 只阻止通过当前类型修改属性，不会自动深冻结对象。
- 泛型不是“更高级的 any”，它要保留位置之间的类型关系。
