# 间隔复习与错题使用方法

本课程已经在高风险主题中安排了多道短练习，但“当场做对”不等于已经记住。把同一道题隔一段时间重新从空白思考，记忆会比连续抄写答案更牢。

## 每天开始前的 8–10 分钟

1. 不看笔记，口述昨天最重要的两个概念。
2. 重做昨天的一道短题，先预测输出，再运行。
3. 从三天前选一道易错题，只看题目，不看答案。
4. 从七天前回答一个“为什么”，例如“为什么 `??` 不会覆盖 0”。
5. 把仍然说不清的内容写入下方错题记录。

## 推荐复习间隔

假设今天刚完成 Day 10：

| 时间 | 做什么 |
| --- | --- |
| 当天 | 完成全部练习，解释错误原因 |
| +1 天 | 重做 1 道，不看答案 |
| +3 天 | 重做 1 道修错题，并换一组数据 |
| +7 天 | 把概念用于当天综合题 |
| +14 天 | 只凭记忆写一个最小例子 |

如果 +7 天仍不会，不需要惩罚自己或重学整章；把这道题重新放入 +1、+3、+7 的小循环即可。

这些概念会在不同天重复出现。复习时优先沿着同一行回看：

| 易错点 | 首次学习 | 再次出现 |

## 错题记录模板

复制下面五行到自己的笔记；每条只记录一个错误：

```text
日期 / 题号：
我原来预测：
实际发生：
原因（不用术语也可以）：
下次看到什么信号要想起它：
```

示例：

```text
日期 / 题号：Day08-02
我原来预测：0 || 10 会得到 0。
实际发生：得到 10。
原因：|| 看到假值就换默认值，0 也是假值；?? 只处理 null/undefined。
下次看到什么信号要想起它：有效数据可能是 0 或空字符串时，先考虑 ??。
```

## 怎样重做而不破坏进度

- 先复制自己已经完成的 `practice-XX.ts` 到个人笔记，再把 TODO 部分清空重写。
- 或先阅读题目，在一个临时编辑器窗口从空白写最小版本。
- 运行指定题：`npm run beginner -- day10 02`。
- 运行当天全部题：`npm run beginner -- day10 all`。
- 只核对参考实现：`npm run beginner:solution -- day10 02`。

参考答案的目标是解除卡点，不是要求逐字相同。看过答案后合上它，隔十分钟重新写一遍，才算完成这次复习。
